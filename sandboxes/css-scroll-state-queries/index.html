Styling Scroll State with scroll-state()

Scroll each box. Every change you see — shadows, labels, hints, highlights — comes from an @container scroll-state() query. The JavaScript only switches tabs.

This browser doesn't support scroll-state() queries yet, so the boxes scroll normally but never change style — the fallback every visitor without support gets.

Release notes

Scroll down. As soon as the header reaches the top of this box and stays there, the query scroll-state(stuck: top) matches and the header compacts and gains a shadow.

Before it's stuck, the header sits flat in the flow, looking like part of the page. That's the point: a shadow only makes sense once there's content sliding underneath.

The sticky element itself is the container. It can't style itself from its own query, so the visible styles go on an inner wrapper.

The action bar at the bottom works the other way round. It's stuck to the bottom edge until the end of the article scrolls into view, then it settles into place and loses its border.

No scroll listener, no IntersectionObserver and no sentinel elements are involved. The browser already knows when a sticky element is stuck; this query simply lets CSS ask.
