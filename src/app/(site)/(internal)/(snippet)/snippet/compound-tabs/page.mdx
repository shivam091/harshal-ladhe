## Introduction

Tab components usually start life as one big component with a `tabs={[...]}` config prop — and then grow a new prop every time someone needs a badge in a trigger, a custom panel wrapper, or a disabled tab. Worse, the ARIA wiring (`role="tab"`, `aria-controls`, roving `tabindex`) is easy to get subtly wrong.

This snippet provides a **compound** `Tabs` component: `Tabs`, `Tabs.List`, `Tabs.Trigger`, and `Tabs.Panel` share state through React context, so you compose the markup freely while the component handles IDs, ARIA attributes, and Arrow/Home/End keyboard navigation for you. It works both controlled and uncontrolled.

## The Component

<CodeBlock language="tsx">
{`
  "use client";

  import { createContext, useContext, useId, useState } from "react";
  import type { ComponentPropsWithoutRef, KeyboardEvent, ReactNode } from "react";

  interface TabsContextValue {
    baseId: string;
    value: string;
    select: (value: string) => void;
  }

  const TabsContext = createContext<TabsContextValue | null>(null);

  function useTabsContext(component: string) {
    const context = useContext(TabsContext);
    if (!context) {
      throw new Error(\`<Tabs.\${component}> must be rendered inside <Tabs>.\`);
    }
    return context;
  }

  const tabId = (baseId: string, value: string) => \`\${baseId}-tab-\${value}\`;
  const panelId = (baseId: string, value: string) => \`\${baseId}-panel-\${value}\`;

  interface TabsProps extends Omit<ComponentPropsWithoutRef<"div">, "defaultValue"> {
    value?: string;
    defaultValue?: string;
    onValueChange?: (value: string) => void;
  }

  function TabsRoot({ value: controlledValue, defaultValue = "", onValueChange, ...props }: TabsProps) {
    const baseId = useId();
    const [uncontrolledValue, setUncontrolledValue] = useState(defaultValue);
    const isControlled = controlledValue !== undefined;
    const value = isControlled ? controlledValue : uncontrolledValue;

    function select(next: string) {
      if (!isControlled) setUncontrolledValue(next);
      onValueChange?.(next);
    }

    return (
      <TabsContext.Provider value={{ baseId, value, select }}>
        <div {...props} />
      </TabsContext.Provider>
    );
  }

  const KEY_OFFSETS: Record<string, (index: number, count: number) => number> = {
    ArrowRight: (i) => i + 1,
    ArrowLeft: (i) => i - 1,
    Home: () => 0,
    End: (_, count) => count - 1
  };

  export function TabsList(props: ComponentPropsWithoutRef<"div">) {
    useTabsContext("List");

    function handleKeyDown(event: KeyboardEvent<HTMLDivElement>) {
      const getIndex = KEY_OFFSETS[event.key];
      if (!getIndex) return;

      // Query the DOM so the order always matches what's rendered, including conditional tabs.
      const tabs = Array.from(
        event.currentTarget.querySelectorAll<HTMLButtonElement>('[role="tab"]:not(:disabled)')
      );
      const index = tabs.indexOf(event.target as HTMLButtonElement);
      if (index === -1) return;

      event.preventDefault();
      const next = tabs[(getIndex(index, tabs.length) + tabs.length) % tabs.length];
      next.focus();
      next.click(); // Automatic activation: focusing a tab also selects it.
    }

    return <div {...props} role="tablist" onKeyDown={handleKeyDown} />;
  }

  interface TabsTriggerProps extends Omit<ComponentPropsWithoutRef<"button">, "value"> {
    value: string;
  }

  export function TabsTrigger({ value, ...props }: TabsTriggerProps) {
    const { baseId, value: selectedValue, select } = useTabsContext("Trigger");
    const isSelected = value === selectedValue;

    return (
      <button
        {...props}
        type="button"
        role="tab"
        id={tabId(baseId, value)}
        aria-selected={isSelected}
        aria-controls={panelId(baseId, value)}
        // Roving tabindex: only the active tab is in the page's Tab order.
        tabIndex={isSelected ? 0 : -1}
        onClick={() => select(value)}
      />
    );
  }

  interface TabsPanelProps extends ComponentPropsWithoutRef<"div"> {
    value: string;
  }

  export function TabsPanel({ value, ...props }: TabsPanelProps) {
    const { baseId, value: selectedValue } = useTabsContext("Panel");

    return (
      <div
        {...props}
        role="tabpanel"
        id={panelId(baseId, value)}
        aria-labelledby={tabId(baseId, value)}
        // Hidden rather than unmounted, so every trigger's aria-controls points at a real element.
        hidden={value !== selectedValue}
        tabIndex={0}
      />
    );
  }

  export const Tabs = Object.assign(TabsRoot, {
    List: TabsList,
    Trigger: TabsTrigger,
    Panel: TabsPanel
  });
`}
</CodeBlock>

## How It Works

1. `Tabs` owns the selected value — either internally via `useState` (uncontrolled, seeded by `defaultValue`) or from the `value` prop (controlled) — and calls `onValueChange` on every selection either way.
2. That value, a `select` function, and a `useId()`-generated base ID are shared with every descendant through `TabsContext`.
3. `Tabs.Trigger` and `Tabs.Panel` derive matching IDs from the base ID and their `value`, wiring up `aria-controls` and `aria-labelledby` without you passing IDs around. `useId` keeps them stable across server and client renders.
4. Only the selected trigger gets `tabIndex={0}` (a **roving tabindex**), so Tab moves focus into the tab list once and then straight to the panel.
5. `Tabs.List` handles Arrow Left/Right (wrapping), Home, and End by querying its enabled `role="tab"` children, focusing the target, and selecting it.
6. `useTabsContext` throws a descriptive error if any part is rendered outside `Tabs`, instead of failing silently with `undefined` context.

## Example Usage

<CodeBlock language="tsx">
{`
  // Uncontrolled — Tabs manages its own state
  function SettingsTabs() {
    return (
      <Tabs defaultValue="account">
        <Tabs.List aria-label="Settings">
          <Tabs.Trigger value="account">Account</Tabs.Trigger>
          <Tabs.Trigger value="billing">Billing</Tabs.Trigger>
          <Tabs.Trigger value="team" disabled>Team (soon)</Tabs.Trigger>
        </Tabs.List>

        <Tabs.Panel value="account">Account settings…</Tabs.Panel>
        <Tabs.Panel value="billing">Billing settings…</Tabs.Panel>
        <Tabs.Panel value="team">Team settings…</Tabs.Panel>
      </Tabs>
    );
  }

  // Controlled — sync the active tab to the URL, analytics, etc.
  function ControlledTabs() {
    const [tab, setTab] = useState("code");

    return (
      <Tabs value={tab} onValueChange={setTab}>
        <Tabs.List aria-label="Example">
          <Tabs.Trigger value="code">Code</Tabs.Trigger>
          <Tabs.Trigger value="preview">Preview</Tabs.Trigger>
        </Tabs.List>
        <Tabs.Panel value="code">…</Tabs.Panel>
        <Tabs.Panel value="preview">…</Tabs.Panel>
      </Tabs>
    );
  }
`}
</CodeBlock>

## Use Cases

- **Settings pages** where each section is a panel and triggers need icons, badges, or disabled states.
- **Code/preview switchers** in docs and blog posts.
- **Product detail pages** with Description / Specs / Reviews sections.
- **Dashboards** where the active tab is controlled and mirrored in the URL's search params.
- **Design-system primitives** that teams style freely without forking the behavior.

## Notes & Tips

- **Server Components can't dot into client modules:** `Tabs.List` works inside other client components, but from a Server Component, import the named `TabsList`, `TabsTrigger`, and `TabsPanel` exports instead (or wrap the whole tab set in a small client component).
- **Always label the list:** pass `aria-label` or `aria-labelledby` to `Tabs.List` so screen readers announce what the tabs are for.
- **Automatic vs. manual activation:** this selects on focus, which suits cheap panels. If panels are expensive to render, drop the `next.click()` line and let users press Enter/Space to activate.
- **Keep `value` ID-safe:** values become part of element IDs, so stick to simple slugs like `"billing"` rather than free text with spaces.
- **Vertical tabs:** add `aria-orientation="vertical"` to the list and map `ArrowUp`/`ArrowDown` in `KEY_OFFSETS`.
- **Lazy panels:** `hidden` keeps inactive panels mounted (preserving their state). If that's too heavy, render `null` for inactive panels and accept that `aria-controls` briefly points at nothing.

## Key Takeaway

A compound `Tabs` component trades a sprawling config prop for composable parts that share state through context — `useId` wires up the ARIA relationships, a roving tabindex and Arrow/Home/End handling deliver the expected keyboard behavior, and the same API works controlled or uncontrolled.
