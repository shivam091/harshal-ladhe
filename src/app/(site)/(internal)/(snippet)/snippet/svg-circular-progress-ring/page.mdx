## Introduction

A circular progress ring shows how far along an upload, a quiz, or a profile setup is. It looks like it needs a charting library or some trigonometry, but it doesn't. It's **two `<circle>` elements and one CSS custom property**.

It's the natural sequel to the [one-circle loading spinner](/snippet/svg-spinning-loader). The spinner uses `pathLength="100"` to draw a fixed quarter arc. The ring uses the same attribute, but the arc length comes from a `--progress` variable, so the whole trick is one line: `stroke-dasharray: var(--progress) 100`.

## The Code

<SvgSnippet>
{`
  <svg class="svg-ring" viewBox="0 0 100 100" width="96" height="96" style="--progress: 60" role="progressbar" aria-valuenow="60" aria-valuemin="0" aria-valuemax="100" aria-label="Upload progress">
    <style>
      .svg-ring circle {
        fill: none;
        stroke-width: 10;
      }

      .svg-ring-track {
        stroke: currentColor;
        stroke-opacity: 0.15;
      }

      .svg-ring-value {
        stroke: #6366f1;
        stroke-linecap: round;
        stroke-dasharray: var(--progress, 0) 100;
      }
    </style>
    <circle class="svg-ring-track" cx="50" cy="50" r="42" />
    <circle class="svg-ring-value" cx="50" cy="50" r="42" pathLength="100" transform="rotate(-90 50 50)" />
  </svg>
`}
</SvgSnippet>

<RainbowDivider />

## How It Works

1. The first circle is the **track**: a full ring in `currentColor` at 15% opacity, so it shows on light and dark backgrounds alike.
2. The second circle has the same geometry and sits on top. `pathLength="100"` makes the browser treat its outline as **100 units long**, whatever the real circumference (`2πr ≈ 263.9` here).
3. `stroke-dasharray: var(--progress) 100` draws one dash as long as the progress value, then a gap of `100`. With `--progress: 60` the dash covers 60% of the ring, and the gap is long enough to hide the rest.
4. A circle's stroke starts at **3 o'clock** and runs clockwise. `transform="rotate(-90 50 50)"` turns the value circle a quarter turn back around its centre, so 0% starts at **12 o'clock**. Using the attribute form with a centre point avoids any `transform-origin` setup.
5. `--progress` is set inline on the `<svg>` and inherits down to the circle, so changing the value means changing one property in one place.
6. `role="progressbar"` with `aria-valuenow`, `aria-valuemin` and `aria-valuemax` gives screen readers the actual number, and `aria-label` says what is progressing.

## Variant: A Gradient Stroke

Point the value circle's `stroke` at a `<linearGradient>`. SVG has no conic gradient, so the colour runs across the ring rather than along it. Because the gradient uses the circle's own bounding box, it rotates with the circle: `x1="1"` and `x2="0"` put the start colour where the arc begins, at the top, and the end colour at the bottom.

    <style>

## Variant: Animating Value Changes

When the value changes, the ring jumps. There are two ways to make it glide instead.

**Transition the dash pattern.** Changing `--progress` changes the computed `stroke-dasharray`, and that change can be transitioned like any other property:

<CodeBlock language="css">
{`
  .svg-ring-value {
    transition: stroke-dasharray 0.5s ease;
  }

  @media (prefers-reduced-motion: reduce) {
    .svg-ring-value {
      transition: none;
    }
  }
`}
</CodeBlock>

**Register `--progress` with `@property`.** An unregistered custom property is just text, so the browser can't animate it. Once it's registered as a `<number>`, the variable itself can be transitioned, and anything that uses it updates on every frame:

<CodeBlock language="css">
{`
  @property --progress {
    syntax: "<number>";
    inherits: true;
    initial-value: 0;
  }

  .svg-ring {
    transition: --progress 0.5s ease;
  }

  @media (prefers-reduced-motion: reduce) {
    .svg-ring {
      transition: none;
    }
  }
`}
</CodeBlock>

The first option is enough for the ring on its own. The second is worth it when other styles also read `--progress`, such as a colour that changes near 100%, because they all animate in step.

## Example Usage

Set `--progress` inline to show several values with the same CSS. A `<text>` element in the middle adds a percentage label. `text-anchor="middle"` and `dominant-baseline="central"` centre it on the point `(50, 50)`:

{`

    <style>
      .svg-ring-row {
        display: flex;
        flex-wrap: wrap;
        justify-content: center;
        gap: 1.5rem;
      }

      .svg-ring-row circle {
        fill: none;
        stroke-width: 10;

      <circle class="ring-track" cx="50" cy="50" r="42" />

In a real app, JavaScript sets the value. Update `--progress`, `aria-valuenow` and the label together, so the drawing, the accessible value and the text never disagree:

<CodeBlock language="js">
{`
  function setProgress(ring, value) {
    const progress = Math.round(Math.min(100, Math.max(0, value)));

    ring.style.setProperty("--progress", progress);
    ring.setAttribute("aria-valuenow", progress);

    const label = ring.querySelector("text");
    if (label) label.textContent = \`\${progress}%\`;
  }

  const ring = document.querySelector(".svg-ring");

  // For example, from an upload's progress event
  xhr.upload.addEventListener("progress", (event) => {
    if (event.lengthComputable) {
      setProgress(ring, (event.loaded / event.total) * 100);
    }
  });
`}
</CodeBlock>

## Use Cases

- **File uploads and downloads**, driven by a progress event.
- **Multi-step forms and onboarding**, showing how many steps are done.
- **Dashboards**, for quotas, storage used, or goal completion.
- **Timers and countdowns**, where the ring empties as time runs out.

## Notes & Tips

- **Clamp the value:** keep `--progress` between `0` and `100`. A larger dash is harmless, since the ring is just full, but `aria-valuenow` should never go past `aria-valuemax`.
- **Round caps and small values:** `stroke-linecap: round` adds half the stroke width to each end of the arc, so it looks slightly longer than the real value, and at `0` it can still draw a dot. Use `butt` caps if the ring must read exactly, or hide the value circle when the progress is `0`.
- **Unknown progress:** if you can't measure progress, don't fake it. Remove `aria-valuenow` (a progressbar without it is announced as indeterminate) or show a [loading spinner](/snippet/svg-spinning-loader) instead.
- **The label is not read twice:** a `progressbar`'s children are presentational, so screen readers announce the value from `aria-valuenow`, not the `<text>`. Add `aria-valuetext` if the number needs words, such as "3 of 5 files".
- **Namespace the classes and ids:** a `<style>` inside an inline SVG applies to the **whole page**, and gradient ids must be unique on the page. Use specific names, or move the CSS into your stylesheet.
- **Browser support:** `pathLength`, custom properties in `stroke-dasharray`, and transitions on `stroke-dasharray` work in all current browsers. `@property` is supported in all current browsers too, but only since 2024 in Firefox, so treat the registered version as a progressive enhancement: without it, the ring still updates, just without the glide.

## Frequently Asked Questions

<Details summary="Why rotate the circle instead of starting the path at the top?">
  A `<circle>` always starts its stroke at 3 o'clock, and there's no attribute to change that. Rotating it by `-90`
  degrees around its centre moves the start to 12 o'clock. You could draw the ring as a `<path>` that starts at the top,
  but the rotated circle is shorter and easier to read.
</Details>

<Details summary="How do I make the ring fill anticlockwise?">
  Mirror the value circle after rotating it: `transform="translate(100 0) scale(-1 1) rotate(-90 50 50)"`. The rotate
  still puts the start at the top, `scale(-1 1)` reverses the direction, and `translate(100 0)` moves the mirrored circle
  back into the `viewBox`. If the SVG has no text inside, mirroring the whole thing with `scale: -1 1` in CSS also works.
</Details>

<Details summary="Can the percentage label animate along with the ring?">
  Not inside the SVG with CSS alone, because a `<text>` element's content can't come from a variable. If the label is an
  HTML element on top of the SVG, register `--progress` with `syntax: "<integer>"`, set `counter-reset: progress
  var(--progress)`, and show it with `content: counter(progress) "%"` on a pseudo-element. The number then counts up
  during the transition.
</Details>

<Details summary="Do I have to use pathLength?">
  No, but without it the dash values are in user units. You'd set `stroke-dasharray` to `progress / 100 *
  circumference` and the circumference (`2πr`), and redo the maths whenever the radius changes. With
  `pathLength="100"`, the progress value *is* the dash length.
</Details>

## Key Takeaway

Give the value circle `pathLength="100"` and `stroke-dasharray: var(--progress) 100`, rotate it `-90` degrees so it starts at the top, and put a faint track circle behind it. The ring then follows one custom property, which JavaScript sets alongside `aria-valuenow`, and a transition or a registered `@property` makes changes glide.
