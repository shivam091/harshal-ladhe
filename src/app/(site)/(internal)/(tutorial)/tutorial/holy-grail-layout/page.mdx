## Introduction

The **Holy Grail layout** is a classic web design pattern consisting of a header, three columns (sidebar, main content, sidebar), and a footer. Historically, this layout was difficult to achieve with floats or early flexbox techniques without structural hacks.

CSS Grid makes this pattern straightforward — providing a **clear, semantic, and responsive** solution with minimal code.

<RainbowDivider />

## The Grid Snippet

<CodeBlock language="css">
{`
  :root {
    --sidebar-width: 200px;
    --layout-gap: 0;
  }

  .holy-grail-wrapper {
    display: grid;
    grid-template-areas:
      "header header header"
      "nav main side"
      "footer footer footer";
    grid-template-columns: var(--sidebar-width) 1fr var(--sidebar-width);
    grid-template-rows: auto 1fr auto;
    min-height: 100vh;
    gap: var(--layout-gap);
  }

  header {
    grid-area: header;
  }

  nav {
    grid-area: nav;
  }

  main {
    grid-area: main;
  }

  aside {
    grid-area: side;
  }

  footer {
    grid-area: footer;
  }

  /* Mobile Responsive */
  @media (max-width: 768px) {
    .holy-grail-wrapper {
      grid-template-areas:
        "header"
        "main"
        "nav"
        "side"
        "footer";
      grid-template-columns: 1fr;
    }
  }
`}
</CodeBlock>

## Minimal HTML Structure

Only the wrapper requires a class. All layout positioning is handled by semantic elements.

<CodeBlock language="html">
{`
  <div class="holy-grail-wrapper">
    <header>Header</header>
    <nav>Navigation</nav>
    <main>Main Content</main>
    <aside>Right Sidebar</aside>
    <footer>Footer</footer>
  </div>
`}
</CodeBlock>

This keeps the markup clean and readable while allowing CSS Grid to control layout independently of source order.

## Highlights

- **Semantic naming:** `grid-template-areas` acts as a visual blueprint for the layout.
- **Sticky footer:** `min-height: 100vh` combined with a `1fr` row pushes the footer to the bottom. On mobile, that `100vh` can render taller than what's actually visible behind the browser's address bar — see [Dynamic Viewport Height Units](/tutorial/dynamic-viewport-height-units) for `100dvh`, the fix that tracks the real visible height.
- **Ultra-responsive:** Mobile layout is achieved by remapping areas — no DOM changes required.
- **Configurable:** Sidebar widths are controlled via CSS variables.

## Customization Tips

### Adjust Sidebar Width

<CodeBlock language="css">
{`
  :root {
    --sidebar-width: 240px;
  }
`}
</CodeBlock>

### Remove the Right Sidebar

- Remove the `<aside>` element
- Update the grid areas:

<CodeBlock language="css">
{`
  .holy-grail-wrapper {
    grid-template-areas:
      "header header"
      "nav main"
      "footer footer";
    grid-template-columns: var(--sidebar-width) 1fr;
  }
`}
</CodeBlock>

### Make a Sidebar Sticky

<CodeBlock language="css">
{`
  nav {
    position: sticky;
    top: 0;
    align-self: start;
  }
`}
</CodeBlock>

### Change Mobile Order

Simply rearrange the `grid-template-areas` inside the media query.

## Accessibility Notes

- Semantic elements (`header`, `nav`, `main`, `aside`, `footer`) provide meaningful landmarks for assistive technologies.
- Ensure the **source order matches the logical reading order**, even if the visual layout changes.
- Avoid unnecessary ARIA roles when semantic elements already convey meaning.

## Frequently Asked Questions

<Details summary="Why is it called the Holy Grail layout?">
  Because for years it was a layout everyone wanted and nobody could build cleanly. With floats, getting equal-height
  columns, a footer that stays at the bottom, and the main content first in the source order all at once took
  negative margins and wrapper elements. Grid turned it into a few lines of CSS.
</Details>

<Details summary="Should I use Grid or Flexbox for this layout?">
  Grid. The layout is two-dimensional — the header and footer span every column while the middle row splits into
  three — and that's exactly what `grid-template-areas` describes. Flexbox can do it, but only with a nested flex
  container for the middle row.
</Details>

<Details summary="Does reordering with grid-template-areas affect keyboard navigation?">
  Yes. Tab order and screen reader order follow the DOM, not the visual grid, so moving `nav` visually above `main`
  on mobile doesn't change the order a keyboard user moves through them. Keep the source order sensible and limit
  visual reordering to changes that don't confuse that order.
</Details>

<Details summary="How do I make the sidebars shrink instead of using a fixed width?">
  Replace the fixed width in `--sidebar-width` with something flexible, such as `minmax(10rem, 15rem)` directly in
  `grid-template-columns`, or a `clamp()` value. The `1fr` middle column still takes whatever space is left. See
  [min(), max(), and clamp()](/tutorial/min-max-clamp-functions) for bounding widths like this.
</Details>

This Grid-based Holy Grail layout is:
