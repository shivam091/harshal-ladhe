Let's start with what this post isn't. 2027 hasn't happened yet, so nobody can tell you what CSS will ship in it.
There's no CSS Snapshot 2027 from the W3C yet, browser vendors don't publish dated roadmaps for individual CSS
features, and any article that promises "these features are coming in 2027" is guessing.

What we *can* do is look at the evidence. Features don't appear from nowhere: before a feature works in every engine,
it usually ships in one or two, shows up in a preview build of the next, or gets picked as an Interop focus area. As of
November 2026, there's plenty of that evidence to read.

<Info title="How to read this post">
  This is a list of the CSS features **most likely to become usable across all three engines in 2027**, ranked by the
  evidence available in November 2026. Every version number below is a release that already exists. Nothing here is
  a promise from a browser vendor, and some of these will take longer than a year.
</Info>

In this post, we'll cover:

- The kinds of evidence that predict cross-browser support, and how reliable each one is
- Interop 2026 areas with gaps still to close
- Features in two engines that need a third
- Features that are further away
- What "Baseline in 2027" will and won't mean
- How to track all of this yourself
- Frequently asked questions

For what already became usable this year, start with [What's New in CSS in 2026](/post/css/whats-new-in-css-2026).

## What Counts as Evidence

Not all signals are equal. Roughly from strongest to weakest:

1. **Shipped in two engines, and in the third's preview build.** Safari Technology Preview and Firefox's flags are
   where features are tested before a stable release. Shipping isn't guaranteed, but the work is clearly underway.
2. **An Interop focus area.** Interop is a yearly public commitment by Apple, Google, Microsoft, Mozilla and others to
   make chosen features behave the same everywhere, measured by shared tests. It's a strong signal of intent.
3. **Shipped in two engines, with no visible activity in the third.** Likely eventually, but the timing is unknown.
4. **Shipped in one engine only.** Could be years away, or could stall if the other engines have concerns about the
   design.

Most of the features below combine more than one of these signals.

## Interop 2026 Areas with Gaps Left

Interop 2026's CSS focus areas are advanced `attr()`, container style queries, `contrast-color()`, custom highlights,
media pseudo-classes, scroll-driven animations, scroll snap, `shape()`, and three areas carried over from 2025:
anchor positioning, view transitions and CSS `zoom`.

Many of them already work in all three engines, as the 2026 post covers. The scores measure how consistently they
behave, though, not just whether they exist, so the remaining work is often edge cases rather than missing features.
A few still have an engine missing entirely, and those are the clearest candidates for 2027.

### Typed `attr()`

Typed `attr()` lets an HTML attribute supply a real value, such as a number, a length or a colour, to any property:

<CodeBlock language="css">
{`
  .bar {
    inline-size: 50%;
    inline-size: attr(data-value type(<percentage>), 50%);
  }
`}
</CodeBlock>

It's in Chrome and Edge 133 and Firefox 155. Safari has it in Technology Preview. It's also the core of the "advanced
`attr()`" Interop 2026 focus area. Two engines shipped, the third in preview, and an Interop commitment: this is the
strongest candidate on the list.

The cascade fallback above already works today: browsers without typed `attr()` drop the second declaration and use
the first. The full guide is
[HTML Attributes as Real CSS Values with Typed `attr()`](/tutorial/css-typed-attr), and the classic string form is
covered in [CSS-Only Tooltips with `attr()` and `content`](/tutorial/css-attr-content-tooltips).

### Media Pseudo-Classes

`:playing` and `:paused` match `<audio>` and `<video>` elements by playback state. They've been in Safari since 15.4
and reached Firefox in 150. In Chrome they're in nightly builds, version 158 at the time of writing. With the third
engine already implementing them, and Interop 2026 covering them, they're likely to be usable everywhere soon.

### Scroll-Driven Animations

Technically, scroll-driven animations already work in all three engines, but Firefox only shipped them in 159, the
current release. 2027 is when they become usable without hesitation: as visitors update and the Interop work smooths
out differences, the fallback you write today can become a formality.

## In Two Engines, Waiting for a Third

### Customizable `<select>`

`appearance: base-select` turns `<select>` into a dropdown you can style completely, while keeping native keyboard
behaviour and accessibility. It's in Chrome and Edge 135 and Safari 27, and Firefox has it behind a flag. Two shipped
engines plus active work in the third makes this one of the stronger candidates. See
[Styling a `<select>` Dropdown with CSS `appearance: base-select`](/tutorial/css-customizable-select).

### `text-decoration-inset`

`text-decoration-inset` shortens an underline or other text decoration at each end, so it doesn't run the full width
of the text. It's in Firefox 146, it's in Chrome 157, which is in beta now, and Safari has it in Technology Preview.
All three engines are moving on it, so it's a good bet for 2027.

### `random()`

`random()` shipped in Safari 26.2 and in Chrome and Edge 156. Firefox doesn't support it yet. Because two engines
agree, it's a reasonable candidate, but there's no preview build in Firefox to point to.

### `@function` and `corner-shape`

Both are in Chrome and Edge 139 and in Safari Technology Preview, and neither is in Firefox. Safari's preview builds
make them more likely to reach a second engine in 2027 than to reach all three:

- [`@function`](/tutorial/css-custom-functions-at-function) defines reusable functions in plain CSS, which changes how
  design systems can share logic.
- [`corner-shape`](/tutorial/css-corner-shape) adds squircles, bevels, notches and scoops to `border-radius`.

Both degrade cleanly. A browser that doesn't understand `@function` drops any declaration that calls a custom
function, so a plain value declared first still applies:

<CodeBlock language="css">
{`
  @function --negate(--value) {
    result: calc(-1 * var(--value));
  }

  .pull-up {
    margin-block-start: -1rem;
    margin-block-start: --negate(1rem);
  }
`}
</CodeBlock>

### Other Two-Engine Features

Two more features are in Chrome and Safari but not Firefox: **cross-document view transitions** (`@view-transition`,
Chrome 126 and Safari 18.2) and **`text-wrap: pretty`** (Chrome 117 and Safari 26). Both are safe to use now as
enhancements, since unsupported browsers simply do without them.

## Further Away

Some features have strong support in one engine but little visible movement elsewhere. They may well arrive, but the
evidence doesn't point to 2027 specifically:

- **`if()`** is in Chrome and Edge 137 only, with no Firefox or Safari support, not even in preview. See
  [Conditional CSS Values with the `if()` Function](/tutorial/css-if-conditional-values).
- **`display: grid-lanes`** (masonry) is in Safari 26.4 only. Chrome and Firefox don't support it in a stable
  release.
- **`interpolate-size` and `calc-size()`**, for [animating to `height: auto`](/tutorial/interpolate-size-auto-animations),
  are Chromium-only.
- **Scroll markers** (`::scroll-marker`, `scroll-marker-group`, `scroll-target-group`), used for
  [pure CSS carousels](/tutorial/native-css-carousel-scroll-markers), are Chromium-only.
- **Scroll-state container queries**, **`reading-flow`**, **`animation-trigger`**, **`border-shape`** and
  **`caret-shape`** are all Chromium-only.

None of these are bad bets in the long run. They just don't yet have the second engine or the Interop commitment
that would make a 2027 prediction honest.

## What "Baseline in 2027" Will Mean

If typed `attr()` or customizable `<select>` reaches the last engine in 2027, it becomes **Baseline newly
available**: supported in the current version of every core browser. It doesn't become **Baseline widely
available** until 30 months after that, once most people's browsers have caught up.

So the features that become Baseline in 2027 still need fallbacks for a while, and the features that became Baseline
in 2026, such as anchor positioning, won't be widely available in 2027 either. What does get easier in 2027 is using
this year's arrivals with lighter fallbacks, because more visitors will have updated.

## How to Track It Yourself

Predictions go out of date fast. These are the sources worth bookmarking:

- **Baseline on MDN.** Every MDN reference page shows a Baseline badge and a detailed compatibility table.
- **webstatus.dev.** Tracks Baseline status and browser support across many features at once.
- **The Interop dashboard** at wpt.fyi. Shows the scores for each Interop focus area, per browser, through the year.
- **caniuse.com.** The quickest way to check a single feature, including usage figures.
- **MDN browser-compat-data (BCD).** The open dataset behind MDN's tables and Baseline. Its release notes on GitHub
  list every support change.
- **Preview builds.** Safari Technology Preview and Firefox Nightly release notes are where features appear before a
  stable release.

If the pattern of previous years holds, the Interop 2027 focus areas will be announced early in 2027. That list will
be the best single guide to what the browser vendors intend to work on together for the rest of the year.

## Frequently Asked Questions

<Details summary="Will there be a CSS Snapshot 2027?">
  The CSS Working Group has published snapshots regularly, so one is likely, but none exists yet. Even when it does,
  it will list specifications by stability, not tell you which features you can use. See the 2026 post for what the
  snapshot is and isn't.
</Details>

<Details summary="Should I wait for these features before using them?">
  Not for most of them. Typed `attr()`, `@function`, `corner-shape`, `random()` and `text-wrap: pretty` all degrade
  cleanly when a fallback declaration comes first. Customizable `<select>` falls back to a normal select. Wait only
  when the page can't work without the feature.
</Details>

<Details summary="Why isn't if() higher on the list?">
  Because it has the least evidence. It's in Chromium only, and neither Firefox nor Safari has it in a stable release
  or a preview build. It's one of the most useful features on the list, but usefulness isn't evidence.
</Details>

<Details summary="Is masonry finally coming to CSS?">
  It's arrived in one engine: Safari 26.4 ships `display: grid-lanes`. Chrome and Firefox don't support it in stable
  releases, so for now use it with an `@supports` check and an ordinary grid as the fallback.
</Details>

<Details summary="Where do these version numbers come from?">
  MDN's browser-compat-data as of November 2026, with Chrome and Edge 156, Firefox 159 and Safari 27.2 as the current
  stable releases. Versions are the first stable release with support.
</Details>

## Wrapping Up

Nobody can tell you exactly what CSS 2027 will bring, but the evidence points in a clear direction:

- **Typed `attr()`** has the strongest case: two engines, Safari's preview build, and an Interop 2026 commitment
- **Media pseudo-classes**, **customizable `<select>`** and **`text-decoration-inset`** all have work underway in
  the last engine
- **`random()`**, **cross-document view transitions** and **`text-wrap: pretty`** are in two engines and need Firefox
- **`@function`** and **`corner-shape`** are likely to reach a second engine before a third
- **`if()`**, **`grid-lanes`** and the other single-engine features are further away

The best habit is to check the sources rather than the predictions, mine included. If you'd like to start using some
of these today with proper fallbacks, the tutorials linked throughout this post are a good place to begin.
